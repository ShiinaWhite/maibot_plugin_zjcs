# 杖剑助手

《杖剑传说》MaiBot 公会助手插件。

`杖剑助手` 是一个运行在 [MaiBot](https://github.com/MaiM-with-u/MaiBot) 上的插件（plugin id：`zjcs.guild-notifier`，main 当前候选版本 `0.3.0 RC`；当前生产版本与验收状态见 [PROJECT_STATUS.md](PROJECT_STATUS.md)），基于 MaiBot Plugin SDK 实现。它提供自然语言对话可调用的只读游戏事实查询，并根据本地维护的《杖剑传说》时间线数据，每天定时检查服务器进度，提前向公会 QQ 群发送副本、活动和重要事件通知。

项目从公会真实需求出发，当前核心能力是服务器进度 / 活动 / 副本通知；未来会按公会实际使用需求继续扩展其他实用功能，不会永久限定为通知插件。

## 当前仓库能力（0.3.0 RC）

- **绝对日历事件**：全服同一自然日开启的联动、节日等可使用 `event_date`，不随服务器开服日漂移；

- **每日定时检查**：每天在配置的时间点（默认 09:00，Asia/Shanghai）检查一次本地时间线，不依赖 LLM，不使用外部接口；
- **合并通知**：同一天命中的多个提醒合并为一条消息发给每个群；一次每日检查中，同一群最多发送一条正式合并提醒；
- **多目标 QQ 群**：`group_ids` 支持配置多个群，向所有已配置群发送；
- **按群独立去重**：每个群有独立的已发送记录；一个群发送失败不影响其他群，重启后只补发失败的群；
- **部分失败补齐**：发送成功才记录状态；某群失败时其缺失的提醒在下轮检查中重试，且该群收到的正文只包含它缺失的内容；
- **六类独立提前提醒**：副本、秘宝大作战、宾果抽抽乐、幸运刮刮乐、菲涅克的谜题、遗物池及重要事件，各自使用一个提前提醒天数；
- **0 关闭类别**：某类内容填 `0` 即完全关闭该类提醒；
- **副本准入战力**：副本通知附带时间线中已确认的各难度准入战力，缺失难度不补猜；
- **副本准备建议**：副本提醒除开放时间和准入战力外，还会按副本开放日期提示何时开始攒副本次数（准备日期为副本开放前 1 天），文案使用「今天 / 明天 / 后天 / N天后」相对时间，例如 `准备建议：明天开始攒副本次数。`；
- **秘宝重点奖励**：秘宝大作战通知附带当期已确认的重点奖励；
- **宾果准备建议**：宾果抽抽乐提醒附带 `准备建议：现在开始攒果子，活动开始前至少留20个。` 提示；幸运刮刮乐、菲涅克的谜题当前没有额外准备建议；
- **中文 WebUI 配置**：全部配置项通过 MaiBot 插件配置页管理；
- **S4/S5/S6 赛季锚点**：后期赛季使用独立赛季开始日期计算进度，未开始时留空；
- **指令入口**：`/杖剑传说` 或 `/zjcs` 查看中文指令帮助；指令只在发起指令的当前聊天中响应，不会向 `target.group_ids` 中的其他群广播；
- **`/杖剑传说 预览`**（缩写 `/zjcs 预览`）：预览今天按当前配置会生成的提醒，不影响提醒状态；
- **`/杖剑传说 日程`**（缩写 `/zjcs 日程`）：查询未来 14 天（含今天）已确认的副本、活动与重要事件；只读查询，不受提醒提前天数影响，不写入提醒状态；
- **`/杖剑传说 副本`**（缩写 `/zjcs 副本`）：查询下一个副本详情（包含今天开放的副本；开放日期、距离、已确认准入战力、攒次数建议日期）；只读查询，不受提醒配置影响；
- **`/杖剑传说 进度`**（缩写 `/zjcs 进度`）：查询当前开服天数、赛季进度和前后关键节点；只读查询，不受提醒配置影响；
- **`/杖剑传说 秘宝`**（缩写 `/zjcs 秘宝`）：查询当前期和下一期秘宝的开启时间与重点奖励；已确认具体奖励时给出具体奖励，仅确认类别规律时只说类别，不可靠时明确说明；只读查询，不受提醒配置影响；
- **`/杖剑传说 活动`**（缩写 `/zjcs 活动`）：查询下一项每周轮换活动（宾果抽抽乐 / 幸运刮刮乐 / 菲涅克的谜题）的时间与准备建议；只读查询，不受提醒配置影响；
- **`/杖剑传说 测试`**（缩写 `/zjcs 测试`）：在当前 QQ 群发送一条链路测试消息，不写入业务状态；
- **指令权限**：`command.admin_qqs` 留空列表时所有人都可以使用指令；填写后仅列表中的 QQ 账号可以使用全部指令；
- **确定性通知**：所有通知文本由数据直接生成，不调用 LLM；
- **时间线一致性校验**：日期模型、ID、来源引用和周期数据在发布前自动审计；

## 配置概览

复制 `config.example.toml` 为 `config.toml` 后填写（`config.toml` 不提交到仓库）。日常配置建议直接在 MaiBot WebUI 的插件管理页修改。

```toml
[plugin]
enabled = true

[target]
# 支持配置多个 QQ 群，每个元素是一个群号
group_ids = []

[server]
# 服务器开服日期，用于计算当前是开服第几天
open_date = ""

[schedule]
daily_check_time = "09:00"

[reminders]
# 每类内容一个提前提醒天数；0 表示关闭该类提醒
dungeon_remind_day = 1
secret_treasure_remind_day = 2
bingo_remind_day = 4
scratch_remind_day = 2
fenek_remind_day = 2
event_remind_day = 2

[command]
# 管理员 QQ 号列表；留空则所有人都可以使用指令
admin_qqs = []
```

说明：

- `target.group_ids` 是列表，可添加多个 QQ 群号（字符串，不转数值）；
- `server.open_date` 是服务器开服当天，格式 `YYYY-MM-DD`，“开服第 1 天”即当天；
- 每类提醒使用单个整数提前天数，`0` 表示关闭；
- `command.admin_qqs` 只填普通 QQ 号；留空列表则所有人可用指令，填写后仅列表中的账号可用；
- `target.group_ids` 控制每日与赛季准备自动提醒的投递目标；聊天指令永远只作用于发出指令的当前聊天；
- 时区内部固定使用 `Asia/Shanghai`，WebUI 中隐藏，无需修改；
- `season_dates.s4/s5/s6_start_date` 在对应赛季开始前留空即可。

## 赛季前 36 小时准备提醒（0.3.0 RC）

确认本服的赛季开启时刻后，单独配置精确提醒；以下仅为日期一致时的示例，**不是所有赛季固定 08:00 的规则**：

```toml
[season_preparation]
enabled = true
start_times = [{ season = "S3", start_datetime = "2026-10-10T08:00:00+08:00" }]
```

默认 `start_times=[]`，不自动填入推断时刻。每条记录使用带时区偏移的 ISO 8601 datetime，按 `schedule.timezone` 转换后的日期必须与现有时间线 / `season_dates` 的可靠日期一致。日期未知、时刻无时区、重复赛季记录或日期冲突均跳过。后期赛季仍须先配置其已有日期锚点；开启时刻列表不会覆盖日期锚点。`enabled=false` 可独立关闭该提醒，旧的六类提醒仍按原配置工作。

准备节点是开启瞬间减去 **36 个实际小时**。例如 `2026-10-10 08:00 +08:00` 对应 `2026-10-08 20:00 +08:00`，不受每日 09:00 的检查时间限制。通知表达为本赛季目标完成后“可以考虑”停止领取小床经验；没有加入先推新图再领经验的要求。

准备窗口为 `[season_start - 36h, season_start)`。精确提醒与每日检查共用一个串行任务，避免并发写状态。重启或短暂失败后，在准备节点至赛季开始之前可补齐未成功的群；文案显示剩余实际小时。窗口前直接等待下一每日检查或精确准备节点中较早者。精确发送沿用每次重新解析聊天流的 1/3/5 秒有限重试；只有窗口内存在未成功群或尚未落盘的状态时，才最多每 60 秒补齐一次，并以赛季开始时刻为重试截止。全部可靠持久化后恢复长等待，配置更新通过原生命周期取消并重启调度。每次发送前再次检查过期；赛季已开始则不再发起补发。已发出的网络请求无法在远端收回。

按群持久化去重键包含赛季事件 ID、UTC 开启瞬间和 `36h`，state 继续为版本 2，历史记录保留。相同瞬间的不同偏移写法不会重复；修改开启瞬间会构成新通知。确认发送后如果磁盘写入失败，本进程只重试状态写入；若在成功持久化之前崩溃，跨重启仍可能重复，这与发送和文件写入不能组成事务的边界一致，不声称 exactly-once。

config `1.4.0` 自动补齐新节并升到 `1.5.0`，保留旧目标群、管理员、日期、09:00 和六类提前天数；默认 `start_times=[]` 确保迁移本身不引入新发送；正式部署后，必须由操作者配置本服已确认的赛季 datetime 才会实际触发。Tool / 命令继续按自然日查询，尚不提供本节的小时级倒计时，查询不会生成准备通知。事实模型依据与测试记录见 [0.3.0 RC 验收记录](docs/RC_0.3.0_VALIDATION.md)。

## 数据来源原则

通知内容来自仓库内的本地数据文件 `timeline_v1.json`，数据维护规则见 [DATA_GUIDE.md](DATA_GUIDE.md)：

- 运行时只读本地时间线，不依赖第三方接口；
- 正式服确认数据优先，测试服 / 预测数据不作为确定事实通知；
- `pending` 或未确认内容不通知，缺失数据不猜测。

## 自然语言只读工具

插件新增一个 SDK Tool：`zjcs_query`。MaiBot 可以在普通对话中查询本公会已配置服务器的事实，再自行组织回复。工具本身不发送群聊消息、不调用 LLM，不读取或写入 notification state，不受提醒提前天数、通知目标群和每日检查时间影响。现有斜杠命令继续保留。

| `query` | 查询内容 | 自然语言例子 |
| --- | --- | --- |
| `next_dungeon` | 今天起最近的副本、已确认战力、攒次数日期 | 下一个副本什么时候？下个本要多少战力？下个副本门槛多少？几战力能进？ |
| `next_weekly_activity` | 今天起下一项周常，或指定活动的下一次开启 | 下一次宾果什么时候？刮刮乐还有多久？菲涅克什么时候？ |
| `next_season` | 严格晚于今天的紧邻下一赛季开启日期 | 赛季什么时候更新？ |
| `progress` | 开服天数、当前赛季及进度、前后关键节点 | 现在开服多少天了？ |
| `secret_treasure` | 最近开启的一期及下一期秘宝、奖励可信度 | 下一期秘宝有什么奖励？ |
| `schedule` | 含今天的未来 14 天开启 / 换期日程 | 最近有什么活动？ |

0.3.0 增强了副本战力口语提示：“下个副本门槛多少”“下个本要多少战力”“几战力能进”继续由 LLM 理解并调用 `zjcs_query(query="next_dungeon")`，使用已有各难度 `requirements`；没有新增关键词路由或第二套战力计算。

`query` 为必填枚举；只有 `next_weekly_activity` 可以使用可选参数 `activity`，取值为 `宾果抽抽乐`、`幸运刮刮乐`、`菲涅克的谜题`。省略 `activity` 时查下一项轮换活动；指定时按本地轮换规则寻找该活动的下一次，不把眼前另一活动误当成所查活动。

调用例子：

```json
{"query": "next_weekly_activity", "activity": "宾果抽抽乐"}
```

工具返回 SDK 支持的字典：`success`、`content`（JSON 事实文本）、`facts`（同一事实的结构化对象）。事实中包含 `query`、`as_of`、`timezone`、`source`、`status`、`data`、`reason`；`source.generated_on` 是本地数据集记录日期，`as_of` 是本次查询日期，不代表已联网刷新游戏资料。

- `status=ok`：存在可用查询结果；空日程只表示窗口内没有已确认条目，不保证没有其他活动。
- `status=unknown`：没有可靠日期 / 数据或服务器尚未开服；`success=true` 表示查询完成，`data=null`，LLM 应明确说明不知道。
- `status=error`：参数、配置或本地数据无法读取 / 计算；`success=false`，不暴露配置值、私有路径或原始异常。
- 副本返回原始数值战力和 `requirements_available`；缺失难度不补全，`pending_formal_power` 不返回战力。`confirmed_partial` 仅确认已有字段；`confirmed_with_version_risk` 仍有版本调整风险。
- 秘宝 `reward_mode` 区分具体奖励（`explicit`）、仅类别规律（`rule_fallback`）和未知（`unavailable`）；不能把类别推成具体单品。
- 副本 / 周常包含今天；下一赛季不把今天已开始的赛季称为下一赛季。S4+ 必须配置对应赛季锚点；紧邻赛季缺少日期时返回未知，不跳到更远赛季、不外推赛季长度。
- 时间精度为配置时区中的自然日，开服当天为 Day 1；不提供小时倒计时，也不推测活动结束时间。

**权限边界**：`command.admin_qqs` 继续只限制斜杠命令。Tool 提供公开游戏事实，供 MaiBot 当前可使用该插件工具的对话调用；不按命令管理员列表授权，也不包含测试发送、预览投递、管理或配置修改能力。当前 Core 注入的 Tool 上下文字段不能充当管理员认证。工具使用插件配置的同一个公会服务器，不根据聊天群号切换服务器；`target.group_ids` 继续只控制自动提醒目标。

工具通过 `visibility="visible"` 声明首轮 LLM 可见；模型是否实际选用仍由 MaiBot 决定。MaiBot Runner 必须实际激活插件（`plugin.enabled=true`），禁用插件时不会注册工具。`target.group_ids=[]` 可在不配置自动提醒投递目标的情况下使用查询工具。

当前 main 候选为 **0.3.0 RC / config 1.5.0 / state 2**，已通过外部 Review 的 DEV 主体实现与调度优化已通过独立 merge commit 合入，等待外部 RC Review，尚未部署生产。当前生产仍为 **0.2.0 / `d2bf4d480b5911cac43faeb91edad59ddb1a62df` / config 1.4.0 / state 2**（操作者提供的基线，本轮未连接生产）。DEV 分支保留，未创建 GitHub Release 或 tag。受控验收见 [0.3.0 RC 验收记录](docs/RC_0.3.0_VALIDATION.md)；这些结果不等于真实生产 QQ 全覆盖。历史验收见 [0.2.0 RC 记录](docs/RC_0.2.0_VALIDATION.md)。

## 开发 / 测试

- 插件源码：`plugin.py`、`timeline.py`、`state.py`；游戏数据：`timeline_v1.json`；单元测试：`tests/`。
- 运行测试：在装有 MaiBot / `maibot_sdk` 的环境中执行 `python -m pytest`。
- 代码质量：提交前运行 `ruff check` 与 `ruff format --check`。
- 原则：游戏内容变化优先改 `timeline_v1.json`，不改业务逻辑；插件数据写入 MaiBot 提供的插件数据目录，不写入源码目录。

## 技术边界

**MaiBot Core 是只读依赖。** 本项目的全部功能通过 MaiBot 插件机制与当前 Plugin SDK 实现；如果某需求不改 Core 无法实现，则明确暴露限制，而不是修改宿主。
